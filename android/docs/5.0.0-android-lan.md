## 使用方法

1. 两部设备连同一个 Wi-Fi，或一部开手机热点、另一部连接。无需互联网或账号。
2. 大厅点“局域网联机 · 10 款”，选择游戏；每款游戏的模式菜单也有“局域网联机”。
3. 一人输入昵称并“开一个猪圈”，另一人从房间列表加入。自动查找受限时，输入房主显示的 IPv4 地址及端口。
4. 双人游戏由房主点“两人开始”。斗地猪由房主开始，可给空位补电脑。
5. 双人游戏结束后双方点“准备再来一局”；斗地猪使用原有准备按钮。认输需要在游戏内再点一次确认。

请保持两端游乐场在前台。双人房间有一方进入后台或掉线时暂停接受操作；原手机、原应用会话重新加入可回原座位。房主退出、被系统回收或重启应用会关闭房间，房间不跨应用重启保存。斗地猪保留原有超时和掉线电脑托管。

公共 Wi-Fi 有时禁止设备互相连接，自动查找和输入地址都可能不通，此时换同一手机热点。不开公网房间，不使用互联网中继。

## 实现与信息边界

- 原生 `LanNetwork.java` 通过 TCP 分行 JSON 与 UDP 房间发现通信，兼容既有 `piggy-lan/1`；默认 UDP 47320，建房 TCP 47321–47330。支持端口占用回退、UTF-8 分片重组、心跳、掉线与资源释放。每行最多 256 KiB，写队列有界。
- 页面继续使用固定 HTTPS 虚拟来源和 `connect-src 'none'`，WebView 不直接联网。新增桥只接收有限的建房、查找、地址加入、发送、退出操作；只接受内网 IPv4 地址，不解析任意主机名或访问公网目标。
- 房主独占规则对象并校验座位、轮次、版本和合法操作。过期或重复操作不能再次执行。双人再战需要双方准备；重连令牌只留在握手中，不广播到局面。
- 海战只发送本人的舰队及公开命中记录，不发送对手布舰、种子或存档；轮盘只发送本人的线索，不发送隐藏队列或随机补给袋；斗地猪继续使用按座位过滤的牌桌协议。
- 黑猪8物理仅在房主计算，朋友显示同步球位和结果，不依赖两端浮点模拟恰好相同。
- 手机联机使用独立界面；原来的离线人机、同屏双人、游戏美术与许可证保留。联机不写入离线棋局存档或冒充人机胜场。
- 新增网络状态、Wi-Fi 状态及 Wi-Fi 接收锁权限，不读取位置、通讯录或麦克风。Wi-Fi 非必需硬件；不联机时仍能离线玩。

Android 16 的本地网络限制为按应用选择加入的兼容测试，当前 targetSdk 仍为 36；以后提高到 37 时应按系统要求增加本地网络运行时授权，不能仅修改目标版本。[Android 官方本地网络权限说明](https://developer.android.com/privacy-and-security/local-network-permission)。Wi-Fi 接收锁用于提高房间发现的可用性，退出后释放。[Android 官方 MulticastLock 文档](https://developer.android.com/reference/android/net/wifi/WifiManager.MulticastLock)。

## 验证与可复现构建

已通过：九款新增联机规则的合法/非法操作、完整对局与阶段、国际象棋将死、私密舰队及验弹、台球物理、过期包、后台暂停、同座位重连、双方再战；既有斗地猪三方房间连续八局与托管回归；原生真实 TCP/UDP 的查房、端口回退、UTF-8 分片、超长行、定向发送、广播、踢出及重建；原有资源白名单、题库导入、更新策略及更新网络回归。

另用三个独立 JVM 原生通信实例连接 360px/390px Chromium 手机界面，逐项真实点击完成十款建房、入座、操作与同步；双人游戏完成结算再战，斗地猪完成三人独立手牌、叫分及身份同步；断线重连、前后台暂停、象棋学堂入口、横向溢出和脚本错误检查通过。界面截图逐项检查。

**这些是主机端真实网络和浏览器验证，不等于安卓真机安装或两部实体手机的 Wi-Fi / 热点验收。** 安卓真机、系统 WebView、路由器隔离和厂商省电策略的实际表现尚未实测。

- `python build.py --prepare-only` 生成入口和四套按需引擎分片；入口约 3.90 MB，仍低于既有 6 MiB 上限。
- `node tests/test-lan-games.cjs <共用app目录>`；不传参数时使用本地相邻共用工程。
- `python tools/test-lan-network.py --jdk <JDK> --json-jar <org.json.jar> --work <测试输出>`。org.json 测试依赖可取 [Maven Central 20250517](https://repo.maven.apache.org/maven2/org/json/json/20250517/json-20250517.jar)，仅用于主机测试；Android 自带 org.json，不新增 APK 依赖。
- `tests/test-lan-browser.cjs` 顶部列出环境参数；它调用测试 JVM 的原生网络，不使用模拟联机替代 TCP。
- 使用官方 SDK/JDK 及原签名构建普通 APK；兼容包加 `--legacy-compatible`。构建中间文件输出到指定工作目录。
- 发布附件完成后，从实际 APK 生成普通和兼容清单，显式加 `--native-revision 7`，兼容清单再加 `--legacy`。两份 APK 必须校验原签名、版本、全部 assets 和实际下载摘要。

既有第三方游戏与引擎来源、许可证未改变。新增局域网通信和界面为本项目代码。
