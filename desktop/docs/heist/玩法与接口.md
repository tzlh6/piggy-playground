# 猪猪夺宝：机关乱斗 — 规则与接口 1.0.0

此模块是共用 JavaScript 本地后端。无 DOM、无第三方依赖、无联网服务、无随机命中；同一初始配置和命令序列得到相同结果。当前前端与动画由 Claude 接入。

## 规则

### 目标与轮次

- 2～4 人，每人一只猪；半径 4 的六边形地图共有 61 格。坐标为轴向 `(q,r)`，不是方格行列。
- 六方向顺序：`E (1,0)`、`SE (0,1)`、`SW (-1,1)`、`W (-1,0)`、`NW (0,-1)`、`NE (1,-1)`。
- 2 人使用相对角，3 人使用每隔一个角的位置，4 人使用第 0、1、3、4 角。家门都距中心 4 格；几何对称不等于已验证竞技平衡。
- 每位玩家每回合 2 行动点。移动、推撞、放弹、旋转弹簧、切换闸门各 1 点；结束回合放弃余点。没有同时输入或抢反应时间。
- 以实际存入自己家门的松露计分。默认目标 10 分，背包上限 5，默认最多 24 轮。
- 有人达到目标后，本轮仍全部走完，再比较所有人的已存分数，最高者获胜；同分共同获胜。最后一轮到期同样按已存分数结算，背包不计入总分。不会因某人离目标很远而提前淘汰。
- 第一轮先手由 `first` 指定，后续始终按座位递增循环；连续再战建议轮换 `first`。

### 收集与补给

- 初始中央井为空，六个周边井各 1 颗松露，减少先手一上来独占中央大包的收益。
- 从第二轮开始，每轮开始中央井长 2 颗、最多自然积到 6；周边井各长 1 颗、最多自然积到 2。玩家掉落可使某格暂时超过自然上限，不会被删除。
- 猪猪落到有松露的格子自动捡取，最多装 5 颗。新补给长在猪猪脚下也自动拾取。
- 被推或被炸掉在脚下的物品不会立刻被受害者捡回，需要重新踩入。场上所有松露数量公开。
- 回到自己家立即交存并补充臭臭弹，使“手里弹药＋自己仍在场上的弹”最多为 2。已存积分不会被抢走。
- 别人的家门不可进入；自己家门不会被推，也不会被爆炸命中。家门阻断爆炸射线。

### 四类机关

1. **弹簧**：落入后沿箭头飞 2 格，越过中间格的地形和实体，只处理落点。站在本格或相邻格可花 1 点顺 / 逆时针转 60°。旋转本身不会立刻弹走站在上面的实体。朝关闭的闸门或别人家门弹会撞停；落点是泥坑或地图外则掉落。猪猪和臭臭弹都能触发。
2. **传送门**：落入后自动移到配对出口。出口被占则停在入口；到出口不会立刻传回来。猪猪和弹都适用。
3. **连动闸门**：每组两扇对面的闸门同时开关。站在本格或相邻格可操作。关闭时挡路和挡爆炸；任意一扇上有猪或弹时，整次关闭操作被拒绝且不消耗行动点。
4. **臭臭弹**：放到相邻空格，可以直接放上弹簧或传送门触发机关。不能放家门、泥坑、场外或被占的格子。放置后的第 `玩家人数` 次换人时，先引爆再开始新玩家回合；即每个人都有一整圈的公开反应窗口。推 / 弹射 / 传送不重置引信。

### 推撞与爆炸

- 推相邻猪或弹 1 格；目标是猪时先震落 1 颗松露。目标离开原格后，行动者跟进原格，可能捡到掉落物或触发机关。即使目标撞墙没动，震落仍发生并消耗行动点，预览会展示。
- 推撞可逐个挤动一列实体；家门上的猪不可推动。不能通过主动普通移动挤人，需要明确选“推撞”。
- 爆炸沿六方向各延伸最多 2 格；关闭闸门和家门阻断射线。泥坑不阻挡臭气。碰到另一颗弹会引爆它并停止当前这条射线，连爆按弹编号递增处理。
- 每次爆炸瞬间锁定命中的猪，按座位顺序依次结算：掉 1 颗松露，再沿冲击方向推 1 格；随后正常触发连锁机关。前面的连锁已将某只猪送回自己家门或使其离场时，跳过它的待结算命中。多颗弹可能多次命中同一只猪。
- 如果先结算的击退挤走了同一波中另一只猪，它仍属于该波的命中名单，沿原射线方向从新位置继续受击。演出应遵循事件顺序，不自行实现“同时物理”。
- 跌入泥坑或场外时掉出全部未存松露，按距离最近、再按 q/r 的固定次序散到安全格子。猪离场，下个本人回合从家门返场，拥有 2 点行动；弹掉落则消失，不在坑里爆炸。
- 循环弹簧不会无限运行：同一条连锁重遇相同机关时停在该格；另有 64 次连锁步上限。停下后可以正常离开。

### 边界结算顺序

一条合法指令：扣行动点 → 操作与所有连锁 → 若行动者落水或点数用尽则换人。

换人：`turnEnd` → 若整轮结束则 `roundEnd` → 判胜（满足则直接终局）→ 下一轮补给与脚下拾取 → 增加 `turnNumber` → 炸弹读秒 / 连爆 → 当前玩家必要的返场 → `turnStart`。

因此最后一轮结算后不再处理下一回合的炸弹；本局以已存积分为准。动画时长不会影响任何规则。

## JavaScript 接口

浏览器加载 `heist-core.js` 得到 `PigHeistCore`。Node 用 `require('./app/heist-core.js')`。详细字段定义见 `app/heist-core.d.ts`。

```js
const g = new PigHeistCore.Game({players: 3, first: 0, target: 10, maxRounds: 24});
const v = g.view();                         // 只读用途的深复制快照
const choices = g.legalActions();           // 本回合可提交的命令
const p = g.preview(v.turn, choices[0], v.revision); // 无副作用、含完整连锁
const r = g.act(v.turn, choices[0], v.revision);     // 权威结算
// r = {ok, code, message?, events, view}
```

`players` 为 2/3/4，`first` 为座位编号，`target` 允许 5～30，`maxRounds` 允许 4～40。未知配置字段拒绝；玩家名称、皮肤等不是规则配置。

| 命令 | 示例 |
|---|---|
| 移动 | `{type:'move',dir:'E'}` |
| 推撞 | `{type:'push',dir:'NW'}` |
| 放弹 | `{type:'plant',dir:'SW'}` |
| 转弹簧 | `{type:'rotate',at:{q:2,r:0},step:1}`，逆时针为 -1 |
| 开关闸门 | `{type:'toggle',at:{q:3,r:0}}` |
| 结束回合 | `{type:'end'}` |

`act` 的第三个参数必须是当前 revision；合法指令使 revision 加 1，撤销也提高 revision。失败返回稳定错误码和中文说明，状态不变且事件为空。

| 错误码 | 含义 |
|---|---|
| `BAD_ACTION` / `BAD_SEAT` | 命令形状或座位编号错误 |
| `NOT_TURN` / `STALE` / `OVER` | 未轮到、过期操作或已经终局 |
| `NO_AP` / `NO_BOMB` | 行动点或弹药不足 |
| `BLOCKED` / `NO_TARGET` | 不能进入，或没有可推目标 |
| `BAD_TILE` / `TOO_FAR` | 机关类型不符或距离过远 |
| `OCCUPIED_GATE` | 连动闸门上有实体，不能关闭 |

`view.phase` 为 `playing` 或 `finished`；暂时离场玩家的 `pos` 为 null。`turnNumber` 从 0 开始，每次换人加 1；`round` 从 1 开始。炸弹剩余换人数为 `bomb.dueTurn - view.turnNumber`，不能当秒数显示。

## 动画事件

一次指令返回按实际发生顺序排列的事件。每条有 `id:'revision:序号'` 和 `type`。以下坐标均为 `{q,r}`；具体联合类型在 `.d.ts` 中，可供编辑器补全。

| type | 主要字段 | 展示用途 |
|---|---|---|
| `action` / `ap` | seat, action / ap | 当前行动者与行动点 |
| `move` | entity, entityId, from, to, mode | 行走、推移、跟进、挤动、弹飞、击退 |
| `push` | seat, target `{kind,id}`, at | 拱鼻蓄力和目标提示 |
| `bump` | entity, entityId, at, against, reason | 撞停 |
| `spring` | entity, entityId, at, dir, to | 弹簧压缩；后面 `move` 才是位移 |
| `teleport` / `portalBlocked` | entity, entityId, from/to 或 at/exit | 传送或出口堵塞 |
| `chainStopped` | entity, entityId, at, reason | 循环装置停止，提示可继续正常移动 |
| `pickup` | seat, at, amount, carry, left | 捡宝与地面剩余量 |
| `deposit` / `restock` | seat, amount, score / ammo | 交存积分 / 补弹 |
| `spill` | seat, amount, carry, reason, drops | 松露散落；drops 含各目标格结算后的 count |
| `fall` | entity, entityId, from, to, reason, respawn | 掉泥坑 / 场外；to 可能不在棋盘内 |
| `plant` | seat, bomb, ammo | 放弹、显示编号与到期回合 |
| `rotate` / `gates` | seat, at, from/to 或 group/open/tiles | 转向 / 两处闸门一起开关 |
| `fuse` | bombId, remainingTurns | 每次换人的读秒变化 |
| `explode` | bombId, owner, at, cells | 臭气覆盖的真实格子 |
| `hit` | seat, bombId, at, dir | 受击表情，后续 spill / move 决定变化 |
| `respawn` | seat, at, ammo | 返场 |
| `turnEnd` / `turnStart` | seat, turnNumber，后者含 round/ap | 换人提示 |
| `roundEnd` / `roundStart` | round，前者含 scores | 轮次提示 |
| `supply` | at, amount, count | 井口产出 |
| `finish` | reason, winners, scores, round | 单人或多人胜利 |
| `restored` | 无其他字段 | 撤销后直接用新快照重绘 |

事件不指定毫秒数、美术资源或音效名称。这些由 Claude 控制。离场、跳过演出与暂停不应再调用相同的 `act`。一批动画结束后以返回快照校准画面。

## 存档、安全边界与 AI

`save()` 返回 schema/rulesVersion/config/actions；`Game.load(对象或字符串)` 逐指令合法重放，拒绝版本不符、非法行动和过大存档。`Game.replay()` 返回开局及各步事件。存档不含名称、账号或任何秘密；本地同屏没有远端身份认证。

`simulate(view,action)`、`legalActions(view)` 和 AI 只接收来自本引擎的可信公开快照；它们是推演工具，不是网络输入防线。外部导入一律使用 `Game.load()`。不要把传入 Worker 的任意自制 JSON 当成存档恢复入口。

AI 三档采用固定节点预算而非增加作弊信息：悠闲 60、聪明 240、恶魔 1000。聪明规划完整当前回合；恶魔使用改编自 OpenSpiel 的 MaxN，在每一层按轮到的玩家自己的收益选择回复，再逐层加深。根层最多保留 4 个完整回合计划，对手层最多保留 2 个，因此是选择性搜索，不能保证最优。只采用整层完成的结果，预算不够时退回上一层；`searchDepth` 以完整回合为单位。两人、三人、四人的评价都是各座位收益向量，不假设其他人自动结盟。

`analyze(view,{tier,maxNodes?})` 返回首行动、计划、节点数等；`choose` 只返回行动。自定义 maxNodes 允许 40～5000。固定快照和预算得到固定决策；引擎对 AI 的行动仍执行相同校验。
