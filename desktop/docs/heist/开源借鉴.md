## 已落实到代码

1. `heist-search.js` 将 OpenSpiel 的确定性 MaxN 搜索改为 JavaScript 适配器。保留“每个节点选择当前玩家收益最高的子节点”的核心。增加节点上限与明确的未完成结果；本游戏没有概率节点，因此没有移植机会节点分支。
2. `heist-ai.js` 恶魔难度用 MaxN 考虑多人回应，逐层加深，预算不够就沿用上一个完整搜索层。先枚举当前完整回合，根层保留最多 4 个计划、对手层保留最多 2 个，所以属于有候选裁剪的搜索，不是穷举最优解。
3. 路线估值以弹簧、传送门、闸门后的实际落点图做有向最短路。场上实体占位由真实推演校验，不能拿忽略占位的估值路径冒充行动预览。
4. `tools/benchmark-heist.cjs` 自动进行 2、3、4 人的全聪明对局和“座位 0 恶魔对其他聪明”对局，每组轮换全部先手位置，总计 18 场。保留每场积分、动作数、思考耗时与交互次数。结果见 `benchmark-results.json`。
5. 新增独立三人收益树测试：验证玩家 1 会选择自己的收益，即使那个选择对玩家 0 有利，也不能把他硬当成玩家 0 的敌对联盟。预算不足不会返回只算了半棵树的偏置结果。
6. 现有规则测试继续覆盖空命令、非法行动不改状态、公开快照不泄露可变引用、重复指令拒绝、预览一致性、存档重放、资源守恒、机关循环终止和整轮结算。

## 许可与素材

`app/heist-search.js` 是 Apache-2.0 改编文件，不能把它描述为本项目原创 MIT 文件；其余新增后端代码采用本项目 MIT 许可。

完整 Apache-2.0 许可证随附于 `app/assets/licenses/google-deepmind_open_spiel-Apache-2.0.txt`。已核对 OpenSpiel 固定提交的根目录，存在 LICENSE，无 NOTICE 文件。改编来源和具体修改记录在搜索模块文件头及本文。

`build-single.py` 已支持把该 Apache-2.0 文本与原有 MIT 许可一同内嵌到单文件页面，以便后续安卓构建保留。尚未把新游戏脚本接入该页面。

没有取用上述项目的角色、界面、图片、音效或品牌标识；这些由 Claude 按猪猪游乐场风格制作。

## 尚不能从这些参考推出的结论

自动对打能检查策略差异和明显规则问题，不能替代人类对“有趣”“高难度”和多人围攻体验的试玩。固定地图、固定决策的 18 场结果也不能当作随机总体胜率；不承诺恶魔在每个座位都比聪明强。与 Quoridor、Cornerus 相比，本游戏额外具有机关位移和补给经济，平衡性需要单独验证。

保留当前已选定的机关夺宝玩法；这次借鉴提升其实现与验证依据，没有擅自替换为另一款游戏。
