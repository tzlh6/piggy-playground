# 猪猪游乐场 6.0 养成后端交接说明

2026-11-10 · 后端 API v1 / 存档 v1 · 接收方：Fable

本文是已实现后端的接口与规则说明，覆盖原《重构方案》4.4 节草案。不包含页面、交互或动画设计。

## 1. 交付范围与已定需求

- 一份存档养一只猪，可以改名。
- 养成与斗地猪使用同一个松露钱包；旧斗地猪余额只在首次建立养成存档时迁移。
- 奖励向学习倾斜：游戏每日 120 松露，学习每日 360 松露。
- 启动默认页为养猪页 `home`；这是已确定的产品配置，后端不执行路由。
- 纯离线规则核心，不建服务器、不做账号，不改变游戏规则与胜负。

交付的四个模块均支持 Node `require` 和浏览器全局对象。模块加载不会创建猪、订阅事件或写入存档。

| 文件 | 全局对象 | 职责 |
| --- | --- | --- |
| `app/pet-data.js` | `PigPetData` | 冻结的内容表、数值、条目 id、原因码 |
| `app/pet-rewards.js` | `PigPetRewards` | 结算输入校验与奖励报价，纯函数 |
| `app/pet-core.js` | `PigPet` | 需求、动作、成长、钱包、每日规则、收据去重 |
| `app/pet-store.js` | `PigPetStore` | 注入存储、事务提交、旧数据迁移、备份、导入导出、事件订阅接口 |
| `test-pet.cjs` | — | 后端回归、浏览器全局加载检查、整月模拟 |

浏览器依赖顺序为 `catalog.js` → `pet-data.js` → `pet-rewards.js` → `pet-core.js` → `pet-store.js`。Node 入口会自行加载依赖；依赖现有 `catalog.js` 中的 `SETTLE` 与 `TALLY`，没有新增第三方包。

## 2. 核心接口

```js
const pet = PigPet.create({
  name: '团子',          // 可省略；1–16 个 Unicode 字符，无首尾空白、控制符和尖括号
  now: 1794268800000,    // 必填，Unix 毫秒时间戳
  seed: 42,             // 可省略；0–2^32-1 的整数
  timezoneMinutes: 480  // 可省略；固定 UTC+8，写入存档
});

pet.advance(now);              // 只推进时间
pet.dispatch(action, now);     // 先推进时间，再执行动作
pet.reward(gameEvent, now);    // 先推进时间，再处理完整结算
pet.view();                   // 只读深拷贝；不推进时间，不抽随机数
pet.save();                   // 可序列化深拷贝；不写磁盘

const restored = PigPet.restore(pet.save()); // 也接受 JSON 字符串；不推进时间
PigPet.validate(save);                     // 返回已验证的副本，非法存档抛带 code 的 Error
```

`create` 也接受 `rng: () => number`，只在未提供 `seed` 时调用一次，取 `[0,1)` 的值生成种子。之后使用存档内的随机状态；恢复存档不需要重新提供随机函数。未传种子时由传入的 `now` 确定种子。核心不调用 `Date.now()` 或 `Math.random()`。

`advance`、`dispatch`、`reward` 返回统一结构：

```js
{
  ok: true,
  reason: null,       // 失败时为稳定的字符串原因码
  events: [],         // 发生顺序；只含事实，不含画面或动画信息
  revision: 12,       // 此次调用若有状态变化，只增加一次
  credited: { coins: 3, xp: 6, trait: 1, walletApplied: 0 }, // reward；claim 也返回 credited
  eligible: true     // reward：是否满足该类奖励的时长门槛
}
```

`credited`、`eligible` 仅在相应操作成功时出现，`claim` 的 `credited` 没有 `walletApplied`。`credited` 是最终实际入账额，已扣除日限和容量限制。斗地猪原结算金额的实际到账量独立放在 `walletApplied`，不包含在 `coins` 中。

拒绝动作前仍可能完成合法的时间推进，例如需求下降、自然醒来、跨日更新。因此 `ok:false` 不等于整份状态完全没变；这些变化会出现在 `events` 与 `revision` 中。无效时间或时间倒退则完全不改变状态。

## 3. 动作参数

| `type` | 其他参数 | 规则 |
| --- | --- | --- |
| `feed` | `itemId` | 食物库存消耗 1；饱食 ≥95 拒绝；青草餐不耗库存 |
| `pet` | 无 | 心情 +8，清除连续戳的计数 |
| `poke` | 无 | 连续戳到第三次起心情 -3，最低 15；不奖励经验 |
| `wash` | 无 | 清洁 +50、心情 +4；清洁 ≥95 拒绝 |
| `sleep` | 无 | 开始睡眠；精力 ≥95 拒绝 |
| `wake` | 无 | 主动醒来；未睡眠时拒绝 |
| `play` | `itemId` | 玩具须已拥有；按内容表增加心情、消耗精力，清洁 -2 |
| `buy` | `itemId`, `quantity?` | 数量默认 1；食品最多一次 99，非食品只能 1；校验解锁、余额和库存 |
| `place` | `slot`, `itemId` | 家具与位置匹配且已拥有；`itemId:null` 表示移走 |
| `wear` | `slot`, `itemId` | `slot` 为 `skin`、`accessory`、`costume`；校验拥有状态 |
| `rename` | `name` | 修改唯一一只猪的名字 |
| `claim` | `taskId` | 领取当日已完成任务；每项每天仅一次 |

喂、摸、洗、玩成功各给 2 经验，共用每日照顾经验上限 40。睡眠中拒绝喂、摸、戳、洗、玩，允许购物、改名、摆放和换装。精力不足时拒绝玩具动作。

冷却：喂食 30 秒，免费青草餐额外 120 秒，抚摸 60 秒，洗澡 300 秒，玩具 60 秒，戳 2 秒。所有冷却由核心计算，快照中保存截止时间戳。

## 4. 结算输入契约

### 4.1 通用字段

两类事件均须包含 `eventId` 和 `at`。`eventId` 是本地持久唯一的结算编号，长度 1–160，无控制字符；同一局或同一轮的所有重试使用同一编号。`id` 仍然表示游戏编号，不能拿游戏编号代替结算编号。

同一 `eventId` 第二次入账返回 `duplicate`，即使负载已改变或程序重启也不会再发奖励。成功处理但没有奖励的短局也记收据。当前日期以前的结算返回 `event-expired`；超过当前时间 5 秒的结算返回 `event-future`。日期按存档内固定时区计算。

### 4.2 游戏

```js
{
  type: 'game-end',
  eventId: 'device-session-a/round-17',
  at: 1794268800000,
  id: 'snake',
  level: 'normal',       // 非空字符串，最长 80
  win: null,            // 必须是 true、false 或 null
  record: true,         // 必须是 boolean
  first: false,         // 必须是 boolean
  seconds: 95,          // 有效游玩秒数，0–86400，可含小数
  mode: 'solo'          // solo / duo / lan
}
```

分类和结算口径取自 `PigCatalog`，传入的 `cat` 不参与决策。未知游戏或学习入口伪装成 `game-end` 会被拒绝。刷分类的 `win` 强制归为 `null`；累计胜场游戏的 `record/first` 强制归为 `false`。

斗地猪使用相同事件，额外**必须**有 `truffleDelta`：本机玩家这局的有符号整数松露变动，范围 ±1,000,000,000。核心把牌局松露和养成奖励作为一次事务处理；其他游戏携带该字段会被拒绝。人机与联机都支持同一个钱包。

### 4.3 学习

```js
{
  type: 'study-session',
  eventId: 'device-session-a/study-6',
  at: 1794268800000,
  answered: 10,        // 整数 1–200
  correct: 8,          // 整数 0–answered；题目全对才计 1，自评题沿用自评
  seconds: 180,        // 有效秒数，0–86400
  subject: null        // 可为 null；或长度 1–40 的非空学科字符串
}
```

学习的 `record` 不影响奖励，可随原事件保留。`subject:null` 完全可用，学习统一增长“学识”，没有按学科分属性的前置依赖。

### 4.4 与当前 M1 壳层的差异

这是本轮冻结的输入契约。当前 M1 的 `game-end/study-session` **没有 `eventId`**，斗地猪还没有 `truffleDelta`；因此不能把原事件不作补全就直接视为后端已接通。`bind` 不会猜造结算编号或输赢金额，缺失时按 `bad-event` 返回。

安卓九款双人联机的独立结算分支目前没有发出 `game-end`，不只是 `mode` 字段错误。现有斗地猪仍自行写 `piggy2-ddz-truffles`，这是旧流程；新后端唯一权威余额是养成存档中的 `wallet.balance`。旧键在迁移后只保留为历史数据，不与新钱包双向同步。

本轮交付为独立后端，尚未改变这些现有调用位置，也未把四个模块加到应用启动路径。这些事实不影响直接调用后端接口与执行测试；不代表现有页面已在发放养成奖励。

## 5. 已实现的经济规则

| 来源 | 松露 | 经验 | 属性 |
| --- | --- | --- | --- |
| 合格游戏参与 | 3 | 6 | 所属属性 +1 |
| 单人胜利 / 通关 | 额外 5 | 额外 4 | 无额外属性 |
| 单人刷新纪录，且不是首次成绩 | 额外 10 | 额外 8 | 无额外属性 |
| 今日心愿指定游戏，首次合格单人结算 | 本局上述松露 ×2 | 不翻倍 | 心情额外 +8 |
| 学习每完成一道题 | 无 | 4 | 每完成 5 题 +1 学识 |
| 学习每答对一道题 | 4 | 额外 6 | +2 学识 |
| 学习一轮至少 10 题 | 额外 20，每轮一次 | 额外 20，每轮一次 | 无额外属性 |

游戏参与门槛为有效时间至少 30 秒，该门槛同时约束参与、获胜、纪录与心愿奖励。学习门槛为有效时间至少 `answered × 3` 秒。短局斗地猪的牌局金额仍然结算；养成奖励独立检查时长。

`win:null` 只表示不发胜利奖励，**不取消有效的破纪录奖励**。刷分类不设“基准分”奖励。首次成绩 `first:true` 不算破纪录奖励。同屏双人和联机的养成奖励只有参与部分，没有胜利、纪录或心愿翻倍；斗地猪本身的牌局金额另外按统一钱包规则结算。

| 每日额度 | 游戏 | 学习 |
| --- | --- | --- |
| 松露 | 120 | 360 |
| 经验 | 240 | 720 |
| 属性增量 | 60 | 180 |

任务奖励也计入对应额度，心愿翻倍后再应用额度。不把未发出的余额滚存到第二天。

**统一钱包的扣款与额度：** 斗地猪先处理牌局金额，再处理本局养成奖励。赢钱占用游戏 120 松露额度，额度不足只入剩余额度；输钱直接扣统一余额，最低 0，超出余额的部分记入 `wallet.forgiven`，不形成债务。输钱和购物都不恢复已经用过的每日额度。原始牌局金额仍是输入中的 `truffleDelta`，实际到账可能因额度或余额而不同，以 `credited.walletApplied` 为准。

初始余额 30，带 3 个苹果、2 根胡萝卜以及皮球、食盆、稻草窝。有旧游玩记录或非零旧斗地猪余额时额外送 30。旧正余额完整迁入（总余额最多 10 亿），旧负余额记入豁免，不带入负债。免费青草餐始终可用。

## 6. 时间、成长和内容

- 需求为饱食、心情、清洁、精力，范围 15–100。满量下降速率分别为每 10、16、36、14 小时 100 点，最低停在 15。
- 睡眠每 3 小时补 100 精力，到 100 自动醒来；同一次推进的剩余时间按清醒状态计算。
- 单次离线推进最多计算 48 小时的需求变化，时钟记录推进到实际传入的 `now`，不会分多次补扣被封顶的离线时长。
- 时间倒退返回 `clock-backward`，不扣需求、不发奖励、不更换心愿、不刷新日限。
- 固定存档时区默认 UTC+8，午夜刷新额度、任务和心愿。设备显示时区变化不会自动改变存档时区。
- 升到下一等级所需经验为 `40 + 20 × (当前等级 - 1)`。最大 100 级；1–4 奶猪仔、5–14 小猪、15–29 少年猪、30 起大猪。
- 五项属性对应益智→聪明、敏捷→灵巧、街机→勇气、对战/棋类→谋略、学习→学识。属性只用于养成解锁。
- 心愿每天从 31 个非学习游戏入口抽一个，状态与随机序列随存档保存。
- 三项每日任务：照顾三次、完成十题、答对八题，分别奖励 6/20/20 松露与同量经验。
- 家具固定位置为 `bowl / bed / toys / wall / window / yard`。家具目前不额外改变需求速率。
- 原有 10 配色、10 种可佩戴装饰及 12 套服饰全部可用，另有不佩戴选项。新增徽章需要购买和解锁。
- 物品、价格、等级/属性门槛全部以冻结的 `PigPetData.items/byId` 为准；所有条目 id 都是接口的一部分。

## 7. 快照与事实事件

`view()` 返回独立快照，修改任意嵌套字段不会改变核心。

主要字段：`apiVersion/revision/name/petCount/level/stage`；`xp:{total,inLevel,toNext}`；`needs`；`status/sleeping`；`traits`；`truffles/wallet`；`inventory/owned/placements/look/wardrobe/unlocked`；`wish/tasks/daily`；`cooldowns/diary/lastNow/timezoneMinutes`。

`status` 按优先级为 `sleeping / tired / hungry / dirty / grumpy / idle`，低需求阈值为 30。需求保留小数，未强制取整。`truffles` 等于 `wallet.balance`，`wallet.ddzNet` 为迁移之后斗地猪实际入账的净变动，`wallet.forgiven` 为旧负余额及牌局亏损超出可扣余额的累计值。

`daily.game/study` 是已经使用的额度，`daily.limits` 给出上限。`tasks` 每项含 `progress/done/claimed`；`cooldowns` 是绝对截止时间。日记最多 160 条。

事实事件包括：`need/refuse/xp/level-up/stage-up/trait/truffle/unlock/wish-new/wish-done/task-done/diary`，以及 `feed/pet/poke/wash/sleep/wake/play/buy/place/wear/rename/claim/reward/offline-cap/import`。事件具体负载可在 `test-pet.cjs` 与对应动作实现中核对；`truffle` 总会给实际 `amount` 与变动后的 `balance`，`reward` 包含结算编号和实际入账明细。

原因码完整表是 `PigPetData.reasons`。常见拒绝为 `too-full / too-tired / sleeping / cooldown / locked / no-money / not-owned / not-enough / already-claimed`。无效事件为 `bad-event`，重复事件为 `duplicate`。

## 8. 持久化接口与迁移

```js
const opened = PigPetStore.open({storage, now, name:'团子', seed:42});
// storage 只需同步 getItem(key) / setItem(key, text)，与 localStorage 接口一致
// 成功：{ok:true, reason:null, created, recovered, events, service}
// 失败：{ok:false, reason, events:[]}

const service = opened.service;
service.view();
service.save();
service.advance(now);
service.dispatch(action, now);
service.reward(gameEvent, now);
const fileText = service.export();
service.import(fileText, now);                 // 整份替换，不叠加余额或见面礼
service.import(fileText, now, {allowOlder:true}); // 显式允许恢复更早进度
const off = service.bind(eventBus, {now:clock, onResult:(result,event)=>{}});
off();
```

存储服务的三个变更接口与核心同名，并额外返回 `persisted`。核心计算在候选副本中进行，只有写入成功才提交为当前内存状态；写入失败时不提交奖励和收据，返回空事件数组，可以用同一结算编号重试。调用 `save()` 和 `export()` 只生成数据，不改变存储。

`bind` 订阅 `game-end` 与 `study-session`，使用注入的时钟，每次处理结果交给可选 `onResult`；返回取消订阅函数。输入仍必须满足第 4 节，不会自动补关键字段，也不改变游戏存档。

主键 `piggy2-pet`、备份键 `piggy2-pet-bak`。文件外层有格式、版本和校验和；校验和用于发现损坏，不是数字签名。每次提交前备份上一份已经验证的好存档，坏主档不会覆盖好备份。主档损坏时回退备份；两份都坏时报告错误，绝不静默新建猪。未来版本存档返回 `save-newer`，不自动降级覆盖。

首次建立存档读取 `piggy2-ddz-truffles`、`piggy2-play-stats`、`piggy2-look`、`piggy2-acc`，主档或备份已经存在就不再发迁移礼。旧键全部保留；新钱包不再从旧余额自动累加。

导入支持本模块导出的文件文本，也支持合法的核心存档 JSON 文本。默认拒绝时间或同时间修订号更早的存档，防止误覆盖；`allowOlder:true` 是显式回档。导入会验证、推进时间并持久化，失败不替换当前猪。

每次写入检查主档是否在本服务之外发生变化，检测到时返回 `save-conflict`。这提供过期写入检测，不把普通 `localStorage` 宣称为跨窗口原子数据库。完全离线的时钟和可编辑存档也不提供防篡改认证。

## 9. 验证与当前边界

后端回归命令：`node test-pet.cjs`，最终 21 组通过。已加入本地 `package.json` 的完整回归命令，本地 24 个回归入口全部通过。本机没有 `npm` 命令，实际按该命令中的相同顺序逐项调用 Node，未跳过任何入口。

覆盖全部 32 个入口的分类、需求与睡眠、全部动作、奖励差异、日限、午夜与倒退、心愿和任务、成长、钱包迁移、重复事件、非法数据、存储故障、备份回退、导入导出、并发写入检测，以及 31 天共 744 个小时节点的混合养成模拟。另在 Node vm 中模拟浏览器全局方式加载四个模块，并让 `Date.now/Math.random` 抛错，检查核心不读取隐式时钟或随机数；这不是浏览器页面或真机走查。

本轮没有改页面或动画，没有把这些模块接入既有游戏的实际结算，也没有构建 EXE/APK 或修改版本号、更新清单。本地运行页面仍是已有 M1 状态，后端可以独立使用；完整界面、真机存储和真实联机结算不属于本轮已验证范围。公开源码本轮只同步后端相关增量，不携带本地尚未发布的 M1 前端；因此公开分支的完整测试为原 22 个入口加本轮后端入口，本地额外包含 M1 壳层测试。
