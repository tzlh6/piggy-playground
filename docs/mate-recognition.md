# 杀法识别的依据与边界

`app/mate-patterns.js` 是无 DOM 的终局分类模块；胜负由原有规则引擎裁定，分类不修改棋局，也不调用搜索引擎。只有真实将死才标注国际象棋杀法；中国象棋额外区分困毙和擒将。国际象棋逼和、认输、普通将军不会触发绝杀。

## 开源参考

- [ornicar/lichess-puzzler 的杀法标注代码](https://github.com/ornicar/lichess-puzzler/blob/8e24b6d5e2b9618e41581a327926e4ac67c610a2/tagger/cook.py)：这是 Lichess 习题生成系统的实际识别实现。对照其闷杀、底线杀、阿纳斯塔西娅杀、阿拉伯杀、波登双象杀、钩子杀、燕尾杀的几何条件；`test-mate-patterns.cjs` 也重放其 `test.py` 中四个底线杀正反例。
- [BobJackson/chess 的中国象棋识别模块](https://github.com/BobJackson/chess/blob/4b7279bd66436c2e51c3f711f1cffcd6ff3451af/miniprogram/core/mate.js)及其 [FEN 测试局面](https://github.com/BobJackson/chess/blob/4b7279bd66436c2e51c3f711f1cffcd6ff3451af/scripts/fixtures/mate-cases.js)：对照炮架关系、卧槽／挂角／钓鱼／侧面虎马位以及车兵封门。它是小型项目，不能与 Lichess 的应用规模等同。
- [daihengdh/XiangQi-online 的 detectMateType](https://github.com/daihengdh/XiangQi-online/blob/d666ec7168f1beeb1815179b6ba42cef3ffa2245/public/js/rules.js)：作为中国象棋第二份实现对照。不能仅因现存双车或双炮就认定经典杀法。
- [denialguo/chesstrove](https://github.com/denialguo/chesstrove)：补充参考终局攻击、封路和参与棋子的组织方式。

参考算法的棋理判据与局面数据，运行代码和矢量特效独立实现；没有复制或打包这些项目的代码、美术或依赖。

## 本实现的具体约束

- 用真实棋子攻击关系寻找将军子；计算逃路控制时先移走老国王，并模拟其落到目标格，避免遮挡和吃子造成的假封路。马腿、象眼、炮架和将帅照面按棋种处理。
- 闷杀要求马将军且所有邻格均被守方棋子占据；底线杀要求朝前邻格被守方棋子堵住。阿拉伯杀要求角落、贴身车和两格对角的保护马；波登双象杀要求不同颜色的象分居国王两侧，且实际控制逃路。
- 双车错采用更严格的过程条件：最近三次本方行动须为两辆车 A-B-A 交替将军，并有另一车实际封路。只有终局双车的旧存档不会据此猜测过程。新存档保留最近八个半回合，续局时校对它们与原有行动记录一致。
- 马后炮必须真的以本方马作炮架；重炮以本方炮作炮架；夹车炮还要求车参加封路；天地炮要求纵向炮与底线炮同时将军。挂角、卧槽、钓鱼和侧面虎以防守方九宫的镜像坐标识别。
- 铁门栓要求车／兵占住将前方，中炮隔着该子牵制原本能吃它的士。无关的中炮不算。
- 同一终局可能有多个真实特点：主名称选择具体模式，结算文字另列同时成立的标签。没有充分依据时用车线绝杀、炮轰绝杀或合围绝杀等通用名称。没有穷举所有传统杀法，尤其不凭静态终局猜测复杂过程型名称。

`node test-mate-patterns.cjs` 覆盖典型形状、黑白镜像、合法开局杀、双将、升变、吃过路兵、双车错过程、反例以及与规则引擎的攻击判断一致性。特效只消费分类得到的棋子与线路；重看不再次结算，不改盘面或成绩，悔棋和新局会清除旧特效。

## 军师猪绝杀动画

`app/board-commanders.js` 在棋盘两侧画两只军师猪（SVG 层与棋盘画布同坐标），与 `board-ui.js` 的 `drawMateScene` 共用时间轴 `PigCommanders.MATE`：定格 → 点兵（扇尖逐一指向参与将杀的子，子翻面亮出猪脸并踩出蹄印）→ 封路（逃路格立起栅栏）→ 一指（猪鼻印章）→ 按 `effect` 类别的招式点缀与名局彩蛋 → 卷轴。无论哪方获胜、第几次出现、是否重看都完整播放约 5.2 秒，可点“跳过”或按 Esc；系统开启减少动态效果时直接显示终局静态画面。
