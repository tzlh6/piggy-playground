# 安卓 4.4.4 更新修复（2026-10-16）

用户报告手机当前为 4.4.3，检查更新仍显示最新。实际原因是旧 `UpdatePolicy.validate` 强制 `versionCode = major*10000 + minor*100 + patch`；此前 4.4.4 / 40502 被拒绝，选择器可能随后采用旧 4.4.3 清单。已使用原代码复现“版本编号不一致”，不是只看网上清单版本。

## 修复和交付

- [更新修正版发行页](https://github.com/tzlh6/piggy-playground/releases/tag/v4.4.4-android-updatefix)。显示版本保持 4.4.4；20 款游戏内容保持，Windows 和离线网页未改。
- 旧 `android/update.json` 指向同签名兼容包 4.4.4 / 40404，旧 4.4.3 策略已实际接受。该包安装后使用新更新器。
- 新 `android/update-v2.json` 指向 4.4.4 / 40503 普通修正版，可手动覆盖 4.4.3、临时 4.5.1 和 4.4.4 初版。新版内部编号独立递增，原包名、SHA-256、大小和签名验证及拒绝降级仍保留。
- 两个 APK 的原生 DEX、内置网页与发行证书逐字节一致；`nativeRevision=2` 使兼容包升级后不再重复提示安装相同内容。后续原生修订号提高时仍可更新。
- 每次检查生成新请求参数，禁止请求缓存；显示实际成功的更新线路数量。“最新”说明改为当前可连接线路未发现新版，旧清单另显示提示。
- 生成器从实际 APK 读取包名和版本，旧通道生成时强制检查旧编号公式。提供 `--legacy-compatible` 可复现兼容构建。

## 验证

- 44 项更新边界、17 项网络回归通过，包括编号独立递增、旧公式兼容包、同修订兼容包不重复安装、后续新修订、禁止降级、地址来源、大小与 SHA-256。
- 同签名构建、资源对齐、版本、内置网页核验通过；两个 Release 附件实际下载均与本地一致。
- 使用原 4.4.3 的生产网络与校验组件请求真实旧地址，发现 4.4.4 / 40404，并实际下载、校验 SHA-256 通过；新组件对 v2 的 4.4.4 / 40503 同样通过。这是电脑上的原生组件验证，不是手机安装验收。
- 浏览器模拟验证发现新版、检查/下载按钮零参数调用、线路数量、旧清单提示与 390 px 页面；不把它写成手机截图。
- 用户在本次聊天中已反馈：手机 4.4.3 重新检查后“已发现 4.4.4”。手机实际系统安装、安装后运行和成绩保留尚未确认。

新通道 5/5、旧通道 3/5 条实际线路与正式清单一致。旧 Gcore 与 Fastly 仍有缓存，不能称旧通道全线路通过。
